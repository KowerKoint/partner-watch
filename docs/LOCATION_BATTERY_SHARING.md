# 現在地・バッテリー共有 仕様

更新日: 2026-09-01

この文書は、Partner Watchへ現在地とバッテリー共有を追加するための初期仕様を記録する。

## 1. 目的と基本方針

- 緊急時や連絡が取れない場合に、ペア相手の直近の現在地と端末の電池状態を確認できるようにする。
- 常時追跡は行わず、利用者が「現在の情報を更新」を押した時だけ相手端末へ取得を要求する。
- 現在地共有とバッテリー共有は、機微性が異なるため別々に有効・無効を選べるようにする。
- どちらも既定値は無効とし、共有される側が自分の端末で明示的に有効化する。
- 位置履歴や移動経路は作らず、サーバーには最新のスナップショットだけを短時間保存する。
- スクリーンショットの「撮影受付」とは独立した設定にする。Accessibility Serviceは使用しない。

## 2. 利用者から見た動作

### 共有する側

登録済み画面に「現在地とバッテリーの共有」セクションを追加する。

- 「現在地を共有」スイッチ
- 「バッテリーを共有」スイッチ
- 現在地の精度設定: 「おおよそ」または「正確」
- 最後に相手へ共有した日時
- 位置情報権限、端末の位置情報設定、通知権限など不足している設定の案内

現在地共有を有効にする時は、用途とバックグラウンド取得についてアプリ内で説明してからAndroidの権限設定へ進む。バッテリー共有には実行時権限を要求しない。

### 確認する側

相手の状態カードに以下を表示する。

- バッテリー残量（整数パーセント）
- 充電中、放電中、満充電、不明の別
- 現在地の取得日時
- 位置精度（例: 誤差約30 m）
- 「地図アプリで開く」ボタン
- 「現在の情報を更新」ボタン

初期版ではアプリ内に地図を埋め込まない。緯度・経度をAndroidの`geo:` Intentで端末の地図アプリへ渡す。これによりMaps SDK、APIキー、地図サービス固有の料金設定を追加しない。

表示する値には必ず取得日時を併記し、「現在」という表示だけで古い値を新しい値に見せない。5分を超えた値は「5分前」のように目立たせ、1時間を超えた値はサーバーから取得できないものとする。

## 3. 要求と取得の流れ

1. AがBの「現在の情報を更新」を押す。
2. サーバーはペア、認証、レート制限を確認し、状態取得要求を1件作成する。
3. BがWebSocket接続中なら即時に通知する。未接続または「省電力」の場合はFCMで起床を促す。
4. Bはローカルの共有設定を確認する。
5. バッテリー共有が有効なら、その時点の残量と充電状態を取得する。
6. 現在地共有が有効なら、最大20秒間、新しい位置を取得する。
7. 新しい位置を取得できなければ、15分以内に端末が取得した最終既知位置を代用する。それもなければ位置だけを取得失敗とする。
8. Bは取得できた項目と項目ごとの結果をHTTPSでサーバーへ送る。
9. サーバーはAへ結果を通知し、最新スナップショットを置き換える。

位置取得に失敗してもバッテリー結果は返し、逆も同様とする。要求全体を一括で失敗させない。

FCMには座標、バッテリー残量、認証情報を載せず、要求があることだけを通知する。実データは既存と同じ認証済みHTTPS経由で送る。

## 4. Android権限とバックグラウンド動作

### バッテリー

`BatteryManager`と`ACTION_BATTERY_CHANGED`から残量と充電状態を取得する。特別な実行時権限は不要である。電池の健康状態、温度、充電回数などは初期版では共有しない。

### 現在地

- 「おおよそ」には`ACCESS_COARSE_LOCATION`を使用する。
- 「正確」には`ACCESS_FINE_LOCATION`を使用する。
- アプリが画面に出ていない時の遠隔要求へ自動応答するには、`ACCESS_BACKGROUND_LOCATION`（Android設定上の「常に許可」）を使用する。
- 位置取得中だけ`location`型Foreground Serviceを動かし、端末所有者に見える通知を表示する。取得完了または20秒のタイムアウトで停止する。
- 常時の位置更新、ジオフェンス、移動履歴の収集は行わない。

Androidでは高優先度FCMがバックグラウンド処理開始の契機になっても、位置のような「使用中のみ」の権限には追加制約がある。そのため、アプリ非表示時にも自動で現在地を返す仕様ではバックグラウンド位置情報権限が必要になる。権限を与えない場合もアプリの他機能は使え、現在地だけを`PERMISSION_DENIED`として返す。

画面ロック中でも、本人が現在地共有を有効にしていれば現在地とバッテリーは共有する。画面内容を扱うスクリーンショットとは別の同意として扱う。

## 5. 共有データ

状態スナップショットは少なくとも次を持つ。

| 項目 | 内容 |
|---|---|
| `requestId` | 状態取得要求のID |
| `deviceId` | 観測した端末 |
| `reportedAt` | 端末が結果を送信した時刻 |
| `batteryPercent` | 0から100の整数。共有無効・取得不能時はなし |
| `batteryStatus` | `CHARGING`、`DISCHARGING`、`FULL`、`NOT_CHARGING`、`UNKNOWN` |
| `latitude` / `longitude` | 共有できた場合のみ |
| `accuracyMeters` | Androidが報告した水平精度 |
| `locationObservedAt` | 位置そのものが観測された時刻 |
| `locationSource` | `FRESH`または`LAST_KNOWN` |
| 項目ごとの結果 | `AVAILABLE`、`DISABLED`、`PERMISSION_DENIED`、`SETTING_OFF`、`UNAVAILABLE`、`TIMEOUT` |

端末時刻だけを信用せず、サーバー受信時刻も保持する。位置が未来時刻になっている、精度値が不正、緯度経度が範囲外などの入力は拒否する。

## 6. 保存期間と監査

- サーバーに保存するのは端末ごとの最新スナップショット1件だけとする。
- スナップショットは受信から1時間で失効し、期限後はAPIから返さない。
- 新しいスナップショットを受信したら古いものを置き換える。
- ペア削除時は関連するスナップショットも削除する。
- 緯度、経度、精度、バッテリー残量をアプリケーションログや監査履歴へ記録しない。
- 監査履歴には「状態取得を誰がいつ要求したか」「各項目が成功・拒否・失敗したか」だけを1か月保存する。
- 初期版では端末側にも位置履歴を蓄積しない。現在画面に表示するための最新値だけを保持する。

## 7. 制限値

- 同一端末からの更新要求は1分に1回までとする。
- 同一端末からの更新要求は直近1時間に20回までとする。
- 要求全体のタイムアウトは1分とする。
- 位置の新規取得は最大20秒で打ち切る。
- 代用できる最終既知位置は観測から15分以内とする。
- レート制限には成功、部分成功、失敗を問わず、サーバーが受理した要求を算入する。

位置センサーの連続起動と誤操作を避けるため、スクリーンショットの制限より保守的な値から始める。実機試験後に調整できるものとする。

## 8. 通知とプライバシー表示

- 遠隔要求で位置取得を開始した時は「相手からの要求で現在地を取得しています」という通知を表示する。
- 結果送信後は「現在地とバッテリーを共有しました」と端末所有者へ通知する。
- バッテリーだけを共有した場合、位置取得失敗時、共有設定により拒否した場合も、何が共有されたか分かる文言にする。
- 相手が取得要求を行ったことは、後から双方が監査履歴で確認できるようにする。
- 共有スイッチを無効にした時は、サーバー上にあるその項目の最新値を直ちに削除する。

## 9. APIとサーバーへの影響（概要）

実装時は、既存のペア認証、WebSocket、FCM、保留要求取得を再利用する。

- 状態取得要求の作成API
- 対象端末が保留中の状態取得要求を取得するAPI
- 対象端末が部分結果を報告するAPI
- ペア相手の最新スナップショットを取得するAPI
- 共有無効化時に保持値を削除するAPI
- `status.requested`、`status.completed`相当のイベント

位置・バッテリーデータをスクリーンショット要求テーブルへ詰め込まず、共通の配送部分だけを再利用する。詳細なパスとJSONスキーマは実装着手時にOpenAPIへ追加する。

## 10. 推奨する初期実装範囲

1. バッテリー共有と表示
2. アプリ表示中の位置共有と権限UI
3. バックグラウンド位置権限とFCM起床による遠隔取得
4. 失効、監査、共有無効化時の削除
5. Pixel 8aとAndroid Emulator 2台での実機相当試験
6. Galaxy A25 5Gでの権限画面とバックグラウンド動作確認

バッテリーを先に通すことで、要求配送と部分結果のAPIを位置権限の問題から分離して検証できる。

## 11. 確定事項

以下を2026-09-01に初期仕様として確定した。実機試験でAndroidの制約や実用上の問題が判明した場合は、理由を決定ログへ記録したうえで変更する。

1. 共有は要求時だけとし、定期送信や移動履歴を実装しない。
2. 現在地とバッテリーを別々のスイッチにし、どちらも既定で無効にする。
3. 位置精度を端末所有者が選び、既定を「おおよそ」にする。
4. アプリ非表示・画面ロック中にも自動応答するため、「常に許可」の位置権限を求める。
5. 最新スナップショットだけを1時間保存し、位置履歴を作らない。
6. 位置取得20秒、最終既知位置15分、要求全体1分を採用する。
7. 更新要求を1分に1回、1時間に20回へ制限する。
8. 地図はアプリ内へ埋め込まず、端末の地図アプリで開く。
