# 通知転送 仕様

更新日: 2026-09-10

## 1. 初期仕様

- Android端末へ表示された通知を、ペア相手の端末へPartner Watchの通知として転送する。
- Androidは通知がFCMなどのプッシュ配信由来か、アプリ内で生成されたものかを確実に区別できないため、初期版は端末へ表示された通知を対象とする。
- 転送は端末ごとの設定とし、既定値は無効にする。
- 有効化にはAndroidの「通知へのアクセス」を端末所有者が明示的に許可する必要がある。
- 受信側ではアプリごとに通知を偽装せず、すべてPartner Watchの単一通知チャンネルから表示する。
- 受信通知チャンネルは既定でサイレント（音・バイブレーションなし）とする。利用者はAndroid設定で変更できる。
- Partner Watch自身の通知、常駐通知、グループ要約、タイトルと本文がともに空の通知は転送しない。
- 初期版ではアプリ名、パッケージ名、タイトル、本文、元の通知時刻を転送する。アイコン、画像、操作ボタン、PendingIntentは転送しない。
- 通知の更新も新しいイベントとして扱うが、短時間に同一内容が再通知された場合は端末側で抑制する。

## 2. 配送と保存

1. 送信端末の`NotificationListenerService`が通知を取得する。
2. 端末の転送設定と除外条件を確認し、認証済みHTTPSでサーバーへ送る。
3. サーバーは相手側に属する各端末の配送行を作成する。
4. 接続中の端末にはWebSocket、未接続端末にはFCMで新着だけを通知する。
5. 受信端末は認証済みHTTPSで本文を取得してPartner Watchのサイレント通知を表示し、受領をサーバーへ報告する。

FCMデータには通知タイトルや本文を載せず、取得を促すイベント種別だけを載せる。通知本文と未受領の配送行は作成から1時間で削除する。アプリケーションログと監査履歴へタイトル・本文・パッケージ名を記録しない。

## 3. 制限

- アプリ名は120文字、パッケージ名は255文字、タイトルは500文字、本文は4,000文字までとする。
- 1送信端末につき10秒間に20件、1時間に500件までとする。
- サーバーが受理したことは配送完了を意味しない。FCM停止、受信端末の通知拒否、オフラインが1時間を超えた場合は表示されない。
- HTTPSで経路は暗号化するが、初期版ではE2EEを行わないためサーバー管理者は保存中の本文を読める。このリスクは自宅運用と1時間保持で受容する。

## 4. 複数端末・他OSへの拡張

現在の`slot 1`と`slot 2`は「端末」ではなく、将来はペア内の「利用者側」を表す識別子として扱う。通知イベント本体と端末ごとの配送状態を分離し、送信元と反対側に登録された全端末へ配送できる構造にする。

- Android: FCMとWebSocketを利用する。
- Linux/Windows: WebSocketまたは定期取得を利用する。
- iPad: APNsを利用する。
- 各端末は個別の認証鍵、表示名、プッシュトークン、失効状態を持つ。
- 将来の登録変更では`devices(pair_id, slot)`の一意制約を外し、同じslotへ複数端末を登録できるようにする。
- ある端末で通知を受領しても、同じ利用者側の別端末の配送状態は独立させる。

複数端末の登録UI、端末失効、Android以外のクライアントは今回の実装範囲に含めない。
